# Biz Arena v0.1 — stabilization phase 1

Первая фаза после закрытия Milestone 11 посвящена не новым системам, а доведению уже существующего цикла матча до стабильного и повторяемого состояния.

## Цель фазы

- убрать критичные и частые UX/runtime-сбои в core loop;
- собрать повторяемый smoke-набор для lobby, match, Intel и result flow;
- выровнять интерфейсные формулировки, feedback и пустые состояния;
- собрать backlog регрессий перед следующей фазой hardening.

## Scope

### 1. Core flow bug bash

Проверить вручную и задокументировать:

1. создание комнаты и вход второго игрока;
2. ready-flow и старт матча;
3. pause / resume / reset;
4. действия в Operations-вкладке;
5. Intel-вкладку: CEO brief, focus-plan, pivot preview, execution queue;
6. завершение сезона и экран результатов;
7. сохранение и загрузку комнаты в lobby и после старта матча.

### 2. UI / UX consistency pass

Проверить и при необходимости исправить:

- одинаковые названия сущностей между Overview / Operations / Intel / Events / Results;
- понятные статусы кнопок и disabled-состояния;
- единообразный feedback после бизнес-действий и host actions;
- локализации ru / en / tt для новых или спорных строк;
- пустые состояния без "мертвых" экранов и пустых карточек.

### 3. Smoke matrix

Ниже минимальный набор сценариев, который должен пройти QA после правок.

#### Smoke A — lobby

- host создаёт комнату;
- второй игрок входит по коду;
- оба игрока выставляют ready;
- host стартует матч без ошибок.

#### Smoke B — basic economy

- игрок покупает сырьё;
- меняет цену или продукт;
- проходит хотя бы один тик;
- UI показывает обновлённые деньги, склад и last tick breakdown.

#### Smoke C — Intel

- Intel появляется после входа в матч;
- виден CEO brief;
- focus-plan сохраняется;
- pivot preview и execution queue обновляются после действий;
- хотя бы один actionable queue step запускается из Intel.

#### Smoke D — contracts / research

- берётся контракт из board;
- запускается исследование;
- через несколько тиков отображаются прогресс контракта и research status;
- рекомендации Intel реагируют на изменение состояния.

#### Smoke E — save / load

- host сохраняет комнату;
- состояние комнаты заметно меняется;
- сохранение загружается обратно;
- игроки, room settings и ключевые показатели восстанавливаются ожидаемо.

## Артефакты фазы

К концу фазы в репозитории должны появиться:

- список найденных багов / UX-шероховатостей с приоритетами;
- обновлённый smoke checklist;
- короткий changelog исправлений;
- решение, какие регрессии идут во Phase 2 hardening.

## Definition of done

Фаза считается завершённой, когда:

- нет blocker-багов в сценарии lobby → match → results;
- Intel, contracts, research и save/load не ломают матч при базовом использовании;
- smoke matrix проходит повторяемо;
- backlog для следующей фазы сформирован и приоритизирован.

## Out of scope

Эта фаза не включает:

- новую крупную механику;
- переписывание storage-слоя;
- полноценные e2e-тесты в браузере;
- новый milestone поверх actionable intel.

Это будет предметом следующих фаз стабилизации и hardening; ближайшая из них описана в `docs/v0.1-stabilization-phase-2.md`.
