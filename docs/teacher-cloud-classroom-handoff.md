# Biz Arena Cloud Classroom: короткая инструкция преподавателю

## Что открыть

После установки на сервере КАИ преподаватель открывает:

```text
http://SERVER-IP/server
```

Если подключен домен и HTTPS:

```text
https://YOUR-DOMAIN/server
```

Ученики открывают ссылку из панели преподавателя или QR:

```text
http://SERVER-IP/client
```

## Первый запуск

1. Откройте `/server`.
2. Зарегистрируйте первый аккаунт преподавателя.
3. Создайте комнату.
4. Покажите QR или отправьте ссылку ученикам.
5. После создания первого аккаунта попросите администратора закрыть регистрацию преподавателей.

Команда для администратора:

```bash
sudo sed -i 's/^BIZ_ARENA_ALLOW_REGISTRATION=.*/BIZ_ARENA_ALLOW_REGISTRATION=false/' /etc/bizarena/bizarena.env
sudo systemctl restart bizarena
```

Ученикам аккаунты не нужны. Они входят как гости: имя, компания, код комнаты или готовая ссылка.

## Что видно преподавателю

Панель преподавателя показывает:

- кто вошел;
- кто готов;
- можно ли запускать матч;
- кто застрял на первом ходе;
- кто без закупки, работников, сборки или заявки;
- команды `Пауза`, `Продолжить`, `Следующий ход`, `Завершить`;
- ссылку и QR для входа учеников.

Paused-комната сохраняет состояние в SQLite. После повторного входа преподавателя `/server` показывает ту же фазу и разрешает `Продолжить`. После `Завершить` открывается преподавательский разбор; ученикам передаётся только личный итог без teacher-only методички.

## Проверка здоровья

Откройте:

```text
http://SERVER-IP/api/health
```

Нормальный ответ содержит:

```json
{"ok":true}
```

Для проверки режима сервера:

```text
http://SERVER-IP/api/meta
```

Ожидается:

```json
{
  "deployment": "cloud",
  "storage": {
    "backend": "sqlite"
  }
}
```

В `/api/meta` не должно быть предупреждения о недолговечном хранилище.

## Если cloud-сервер недоступен

1. Запустите Local Classroom на ПК преподавателя.
2. Откройте `/server`.
3. Покажите LAN-ссылку или QR.
4. Если сеть КАИ блокирует LAN, используйте отдельный роутер или точку доступа.
