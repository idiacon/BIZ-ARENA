# Biz Arena Classroom Runbook

## Цель

Запуск в аудитории делится на две роли:

- `BizArena Server` работает на компьютере преподавателя, считает экономику, хранит комнаты и принимает действия игроков.
- `BizArena Client` работает на компьютерах учеников или открывается как обычная страница `/client` в браузере.

Так слабые ПК учеников занимаются только интерфейсом, а все расчеты остаются на сервере преподавателя.

## Быстрый запуск

1. Преподаватель запускает `BizArena Server`.
2. В Server создаёт комнату, выбирает сценарий, сложность, количество ходов и время хода. Для появления в ученическом каталоге включает `Показывать во вкладке «Подключиться»`.
3. Server показывает код комнаты, LAN-ссылку, QR-код и health-ссылку.
4. Ученики открывают `BizArena Client` или LAN-ссылку `/client` в браузере.
5. Во вкладке `Доступные занятия` выбирают нужное лобби и подтверждают вход пятисимвольным кодом преподавателя, затем вводят имя и название компании. Ручной ввод кода и QR остаются доступными.
6. В лобби нажимают `Готов`.
7. Преподаватель запускает матч, когда участники готовы.

## Режимы подключения

1. `LAN` - основной режим. Работает, если ученические устройства видят IP компьютера преподавателя.
2. `Отдельная сеть` - запасной режим без облака. Если вузовская сеть режет устройства друг от друга, подключите преподавателя и учеников к одному простому роутеру или точке доступа.
3. `Localhost/demo` - режим подготовки и показа на одном ПК.

Cloudflare quick tunnel не считается рабочим планом для аудитории в текущем этапе.

## Network Doctor

Server panel показывает:

- IP-адреса преподавательского ПК;
- LAN-ссылку `/client`;
- QR-код для телефона или ученического браузера;
- health-ссылку `/api/health`;
- кнопку `Проверить`;
- подсказки про разные подсети, NAT и client isolation.

Если `/api/health` открывается на ПК преподавателя, но не открывается на ученическом устройстве, проблема в сети аудитории, firewall или изоляции клиентов, а не в игровой логике.

## Панель преподавателя

Server screen - это не игровой экран, а контрольная панель:

- выбор комнаты, компании, метрики и дня;
- готовность класса;
- `Кому нужна помощь`;
- управление матчем: старт, пауза, продолжить, следующий ход, сохранить, добавить бота, завершить, сбросить;
- Client/Health ссылки и QR;
- security summary: принятые/отклоненные действия, replay и playerId mismatch;
- KPI выбранной компании и рейтинг по выбранной метрике.

## Secure Classroom Protocol

- Клиент отправляет `sessionToken` и уникальный `actionId`.
- Сервер определяет настоящего игрока по `sessionToken`.
- Если клиент подставляет чужой `playerId`, действие отклоняется.
- Повторный `actionId` отклоняется как replay.
- Слишком частые действия одного игрока ограничиваются rate-limit.
- Деньги, склад, работники, производство, заявки, host-команды и состояние комнаты проверяются на сервере.

## Проверки перед показом

```powershell
npm run check
npm test
npm run smoke:classroom
```

`smoke:classroom` проверяет:

- server mode отвечает на `/api/meta`;
- `/api/health` возвращает `ok: true`;
- `/api/qr` возвращает SVG QR;
- `/api/network/check` подтверждает локальный health;
- `/server` и `/client` отдаются сервером;
- создание комнаты работает;
- каталог показывает только явно опубликованные лобби без кода, игроков и преподавательских данных;
- выбранное лобби принимает правильный пятисимвольный код и отклоняет несовпадающее подтверждение;
- неправильный `sessionToken` блокируется;
- правильное действие проходит;
- Server admin overview видит комнату и готовность;
- Server admin action может стартовать матч с localhost.

## Если LAN не подключается

1. Убедитесь, что `BizArena Server` открыт на ПК преподавателя.
2. Запустите `tools/Allow-BizArena-Firewall.bat` от администратора на ПК преподавателя.
3. Ученикам давайте IP вида `192.168.x.x`, `10.x.x.x` или `172.16-31.x.x`, а не `127.0.0.1`.
4. С ученического ПК откройте `http://TEACHER_IP:3000/api/health`.
5. Если health не открывается, проверьте firewall, разные подсети, client isolation и маршрутизаторы аудитории.
6. Если сеть вуза закрыта, используйте отдельный роутер/точку доступа или локальный demo-сценарий.

## Если пишет, что игрок уже в игре

В `BizArena Client` измените поле `Имя ученика` на экране подключения. Один и тот же ник считается попыткой вернуться к прежнему игроку.
