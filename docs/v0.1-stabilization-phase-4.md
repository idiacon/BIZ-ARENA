# Biz Arena v0.1 — stabilization phase 4

Четвёртая фаза завершает stabilization track и концентрируется на playtest-качестве, explainability и решении: готов ли проект к статусу `v0.1 stable`.

## Цель фазы

- проверить игру как цельный сезонный опыт, а не только как набор систем;
- улучшить объяснимость решений Intel, queue, contracts и результатов сезона;
- закрыть самые заметные balance и UX-проблемы после hardening;
- собрать финальный выпускной checklist перед фиксацией `v0.1 stable`.

## Scope

### 1. Full-season playtests

Провести несколько полноценных матчей:

- host + второй игрок в LAN;
- host + browser client;
- host + bots;
- сезон до конца с результатами, goals, contracts и research;
- повторное использование save/load в рамках живого матча.

### 2. Balance pass

Проверить и зафиксировать:

- насколько доминируют отдельные operating plans;
- не перегружает ли игрока Intel/queue шумом;
- окупаемость research и contracts;
- влияние board policies и season goals на темп матча;
- качество late-game и финала сезона.

### 3. Explainability pass

Усилить и проверить понятность:

- почему Intel рекомендует именно это;
- почему queue ставит текущий приоритет;
- почему pivot preview говорит "сейчас / позже / не надо";
- почему игрок выиграл или проиграл сезон;
- какие действия сильнее всего повлияли на net worth и progress.

### 4. Release readiness

Собрать финальный пакет перед фиксацией стабильной версии:

- финальный smoke / regression summary;
- список известных ограничений v0.1;
- release note draft;
- решение: открывать ли `v0.1 stable` tag / release note.

## Smoke matrix

#### Smoke A — full season

- матч начинается из чистого lobby;
- проходит до завершения сезона;
- результаты определяются без blocker-сбоев;
- account/career state корректно обновляется.

#### Smoke B — strategic systems

- Intel, focus-plan, pivot preview и queue работают на протяжении нескольких тиков;
- рекомендации заметно реагируют на действия игрока;
- actionable queue steps не ломают стратегический слой.

#### Smoke C — endgame clarity

- final results screen понятен;
- winner logic прозрачен;
- игрок может объяснить, почему именно такой итог получился.

#### Smoke D — release sanity

- README, checklist и stabilization docs не противоречат друг другу;
- команды запуска и проверки актуальны;
- известные ограничения зафиксированы до выпуска.

## Артефакты фазы

К концу фазы должны быть готовы:

- playtest notes;
- список balance / explainability проблем и решений;
- release checklist;
- краткий release note draft;
- решение о статусе `v0.1 stable` и следующем milestone.

## Definition of done

Фаза считается завершённой, когда:

- проект проходит несколько полных сезонных прогонов без критичных blocker-сбоев;
- стратегический слой не только работает, но и понятен игроку;
- основные balance/UX замечания сведены в контролируемый backlog;
- документация и release checklist готовы к фиксации стабильной версии;
- команда может осознанно сказать либо "v0.1 stable готов", либо "нужен ещё один stabilization pass".

## Out of scope

Фаза 4 не включает:

- новый milestone c новыми крупными механиками;
- полноценный live-service rollout;
- переход на иную платформу хранения;
- большой визуальный редизайн;
- расширение игры за пределы v0.1 scope.

После этой фазы можно либо фиксировать `v0.1 stable`, либо открывать следующий продуктовый milestone уже на устойчивой основе.
