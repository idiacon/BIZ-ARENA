# Biz Arena v0.3 Roadmap

## Goal

Prepare Biz Arena for June defense as a complete educational business simulator: playable `.exe`, short live demo, presentation-ready flow, report outline, and optional GitHub publication.

## April - Stabilization And Demo Base

- Align visible versioning around `v0.3.0 Demo Release`.
- Keep old `v0.1-*` documents as archive only.
- Make the KAI demo match the default defense path.
- Confirm the demo uses `KAI Demo Championship`, `AFKAIstudent1`, `motorcycles`, `easy`, 10 turns, and 2 bots.
- Keep browser, LAN, and Electron flows working.
- Run `npm run check` and `npm test` after each implementation pass.

## May - Defense Content And Polish

- Keep the first product goal explicit: Biz Arena as a Simformer-like management simulator, not only a demo shell.
- Deliver strategic decision rounds in factory scenarios (motorcycles first, then drones) with visible consequences and auto-safe fallback.
- Maintain and tune simulation-score ranking so results reflect management quality, not only net worth.
- Keep a live parity map against Simformer-like capabilities in `docs/simformer-parity-matrix.md`.
- Add host-side teacher control for forced strategic rounds so defense flow is deterministic.
- Improve Russian wording on the main defense path while preserving English and Tatar translations.
- Replace technical demo wording with defense-friendly terms: turn resolution, advisor, strategy shift, action queue, contracts, and leaderboard.
- Expand the About screen so it explains the project, game cycle, KAI championship flow, learning value, and delivery package.
- Polish the results screen so the defense has a clear closing point: winner, player rank, company result, debt risk, contracts, research, and top-3 leaderboard.
- Show simulation-score breakdown in the Statistics and Results screens so the rating is explainable during defense Q&A.
- Export a defense-friendly JSON summary with room settings, leaderboard, contracts, market data, and final takeaway.
- Add final screenshots for the presentation and report.
- Map the participant memo requirements to implemented demo features.
- Prepare the slide outline and defense Q&A before filling the final `.ppt` template.
- Polish the explanation of contracts, recalculation turns, production, and leaderboard.
- Prepare the explanatory note from `docs/report-outline.md`.
- Prepare the presentation using the KAI template.
- Convert `docs/report-draft.md` into the final `.docx` explanatory note.
- Generate the draft `.docx` with `npm run report:docx`, then finish formatting manually.
- Fill the KAI presentation template using `docs/presentation-slide-text.md`.
- Capture final screenshots according to `docs/screenshot-shotlist.md`.
- Use `docs/presentation-asset-map.md` to place generated screenshots into slides.

## Early June - Release Package

- Build portable and installer artifacts with `npm run dist:win`.
- If Windows symlink permissions block final packaging, generate the fallback unpacked ZIP with `npm run release:zip-unpacked`.
- Generate the one-file defense transfer archive with `npm run release:defense-bundle`.
- Generate the readiness report with `npm run predefense:readiness`.
- Smoke-test the portable `.exe` on the defense machine if possible.
- Copy the release package using `docs/flash-drive-checklist.md`.
- Rehearse the 3 to 5 minute demo from `docs/demo-script.md`.

## Definition Of Done

- The project launches in browser and Electron.
- The KAI demo match starts in one click and reaches active gameplay.
- Tests pass with `npm run check` and `npm test`.
- The release package includes `.exe`, presentation, report, README, and demo checklist.
- GitHub is ready as an optional publication step, but no push is required without a final decision.
