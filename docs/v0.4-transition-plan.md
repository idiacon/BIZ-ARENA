# Biz Arena v0.4 Transition Plan

## Goal

Version `0.4` should move Biz Arena from a defense-ready prototype into a cleaner classroom game build: easier to explain, easier to maintain, and more replayable for real groups.

## Release Theme

`v0.4` = "Classroom Game Upgrade"

The release should focus on:

- clearer turn decisions;
- better marketing/order-book gameplay;
- stronger teacher controls;
- cleaner code boundaries;
- safer packaged release workflow.

## Non-Goals

- Do not migrate to React/Vite yet.
- Do not replace the current Node/Electron stack.
- Do not add online accounts or external servers.
- Do not rewrite the whole economy in one pass.

## Milestone 0: Stabilize v0.3.1 Upgrade Pack

Target: current branch before starting v0.4.

Tasks:

- Remove obsolete generated release artifacts.
- Remove duplicate test files.
- Keep the current v0.3.0 setup/portable/bundle available.
- Add structured market decision hints.
- Run:

```powershell
npm run check
npm test
npm run screenshots:defense
npm run predefense:readiness
```

Exit criteria:

- `READY_FULL_EXE`
- no duplicate release artifacts from v0.1/v0.2
- marketing screen shows sale risk, best price, current price, and expected units

## Milestone 1: Codebase Boundaries

Target: reduce risk before adding larger features.

### Backend extraction

Create:

- `server/factory/summary.js`
- `server/factory/events.js`
- `server/room/timers.js`
- `server/http/static.js`

Move first:

- `buildTurnChecklist`
- `buildMarketHints`
- `buildTurnReview`
- factory event catalog/generation helpers
- room timer helpers
- static file serving

Tests:

- Keep `test/stabilization.test.js` as end-to-end regression coverage.
- Add focused tests for exported factory summary helpers.

Exit criteria:

- `server.js` drops below 3000 lines.
- Existing tests pass.
- No behavior changes in save/load, timer, or room action APIs.

## Milestone 2: Marketing as a Real Gameplay Surface

Target: make marketing feel like a stock/order-book decision, not a form.

Features:

- Show best market price, player price gap, expected sold units, and sale risk.
- Add visual order-book ladder: cheap offers first, expensive offers later.
- Add "recommended price" one-click button.
- Add "sell all available" one-click button.
- Add warning before ending the turn when stock exists but no sale offer exists.

Server data:

```js
marketHints: [
  {
    kind: 'decision',
    bestPrice,
    recommendedPrice,
    currentPrice,
    expectedUnits,
    saleRisk,
    reasonKey
  }
]
```

Tests:

- high price produces `saleRisk: 'high'`;
- competitive price produces `saleRisk: 'low'`;
- no offer with stock warns before turn end;
- recommended price stays inside scenario price range.

Exit criteria:

- a student can understand whether their sale offer will likely pass before ending the turn.

## Milestone 3: Teacher Control Center

Target: make the teacher able to run a group without inspecting each player manually.

Features:

- Class readiness strip:
  - ready to advance;
  - no production;
  - no sale offer;
  - debt risk;
  - unresolved dilemma.
- Teacher can pause/resume for all users.
- Teacher can force a strategic event.
- Teacher sees "who needs help" sorted by severity.

Server data:

```js
classReadiness: {
  total,
  ready,
  riskBuckets: {
    noSaleOffer,
    noProduction,
    debtRisk,
    unresolvedDecision
  },
  rows: []
}
```

Tests:

- host sees class readiness;
- non-host cannot force events;
- pause/resume changes room status for all players;
- readiness buckets update after production and sale offer actions.

Exit criteria:

- teacher can decide whether to advance the room in under 10 seconds.

## Milestone 4: Turn Review and Learning

Target: each turn should teach the student why the result happened.

Features:

- Post-turn review modal/panel:
  - sold units;
  - missed sales;
  - profit/loss drivers;
  - best bot move;
  - next recommended action.
- Add final "main lesson" on results screen.
- Improve tutorial to point to the new marketing/teacher widgets.

Tests:

- `turnReview` appears after `next-turn`;
- review mentions no-sale case;
- review mentions overpricing case;
- final result includes comparison to leader.

Exit criteria:

- after one turn, a student sees what went wrong and what to do next.

## Milestone 5: UI Polish and Accessibility

Target: the app feels consistent on classroom laptops.

Tasks:

- Audit all visible Russian strings in game screens.
- Replace `window.alert` error flow with in-app toast/banner.
- Check 1366x768, 1600x900, and current in-app browser sizes.
- Ensure buttons do not wrap badly.
- Keep animations subtle and respect reduced motion.

Tests:

- screenshot defense flow;
- browser smoke with no console errors;
- manual click path:
  - start demo;
  - open marketing;
  - create sale offer;
  - pause/resume;
  - next turn;
  - open results.

Exit criteria:

- no obvious layout overlap in the main defense screenshots.

## Milestone 6: Release Automation

Target: make packaging repeatable.

Tasks:

- Add one script: `release:full`

Expected command sequence:

```powershell
npm run check
npm test
npm run screenshots:defense
npm run dist:win
npm run release:zip-unpacked
npm run predefense:readiness
npm run release:defense-bundle
npm run predefense:readiness
```

- Make `release:defense-bundle` include:
  - current setup exe;
  - current portable exe;
  - latest screenshots;
  - readiness report;
  - logo preview;
  - demo script.

Exit criteria:

- one command can create the files needed for a flash drive handoff.

## Suggested Versioning

- `0.3.1`: cleanup + structured market hints.
- `0.4.0-alpha.1`: backend extraction + tests.
- `0.4.0-alpha.2`: marketing gameplay upgrade.
- `0.4.0-beta.1`: teacher control center.
- `0.4.0-rc.1`: screenshots, tutorial, packaging.
- `0.4.0`: classroom-ready release.

## Risk List

- `server.js` extraction can break hidden closure state.
- `public/app.js` changes can create visual regressions quickly.
- Existing RU/EN/TT translations are uneven; new strings should default to RU first but not break language switching.
- Packaged Electron builds are large; keep old generated artifacts out of the repo/workspace root.

## First v0.4 Task

Start with backend extraction of factory summary helpers because it directly supports marketing, teacher readiness, and turn review without changing player-facing mechanics.
