# Biz Arena v1.0: Pilot Validation

Status: active release gate for `1.0.0-beta.1`.

The normative evidence lifecycle, privacy boundary, immutable receipts, and
`FAIL` / `CONDITIONAL` / `PASS` rules are defined in the
[Pilot Gate B-lite runbook](pilot-gate-runbook.md).

## Product Definition

Biz Arena is a competitive classroom business simulator. A teacher starts a session, students independently manage companies during shared turns, and the class then explains why different strategies produced different results.

The v1.0 goal is not maximum economic complexity. The goal is a reliable lesson in which:

- the teacher starts the room in 3-5 minutes;
- a student understands the first turn without a separate manual;
- company decisions affect one shared market;
- the teacher sees who is blocked and why;
- the final debrief explains cause and effect, not only rank and profit.

## Desktop Contract

The current design and QA target is a Windows desktop client from `1000x760` through `3440x1440`.

Primary reference viewports:

- minimum: `1000x760`;
- standard: `1440x900`;
- Full HD: `1920x1080`;
- large desktop: `2560x1440`;
- ultrawide: `3440x1440`.

All controls, classroom status, turn guidance, market data, and teacher actions must remain available throughout this range. Tablet and phone optimization is a later pass; narrow layouts keep basic compatibility but do not define the current visual design.

## First Pilot

Run the first observed lesson with 5-7 students. Keep the existing 30-student rehearsal as the capacity gate, then expand real classroom size only after the first flow is understood.

Recommended session:

1. Teacher starts Server and completes network preflight.
2. Students join by QR or LAN link and mark readiness.
3. Teacher explains the learning objective in no more than two minutes.
4. Students play 5-8 shared turns with one Crisis Card.
5. Teacher finishes the match and opens the class debrief.
6. Results and session history are exported immediately.

## Evidence To Capture

Assign anonymous student identifiers `S1` through `S7` and neutral company
aliases before room join. The Pilot Gate may ingest only the allowlisted
aggregates from the [evidence schema](pilot-evidence-schema.md).

The following detailed observations are optional operational notes outside the
gate. Keep them outside Git, apply the same consent/access/retention policy, and
reduce them to schema-allowlisted aggregate booleans, counts, and rates before
creating the reviewed attestation:

- time from Server launch to a startable room;
- join and readiness time for each anonymous student;
- time to complete the first turn;
- first step where each student became blocked;
- help and pause requests, with categories;
- reconnects, polling fallback, and lost-session incidents;
- incomplete actions when a timer expires;
- market price, unmet demand, unsold inventory, profit, and bankruptcy risk by turn;
- questions raised during the final debrief.

Do not ingest or commit password hashes, session tokens, names, IP addresses,
URLs, raw exports, logs, screenshots, video, or private infrastructure data.
Manual device and classroom records are reviewed attestations, not
machine-verified events.

## Acceptance Gate

The beta is ready for a larger classroom when one complete Pilot Gate run demonstrates:

- room setup in at most 5 minutes;
- every student joins without editing a URL manually;
- at least 80% of students complete the first turn without navigation help;
- the teacher finds a blocked team in at most 15 seconds;
- reconnect or WebSocket fallback does not duplicate a player or lose actions;
- every finished match appears in session history and exports to JSON/CSV;
- the class can explain at least one result using price, costs, demand, inventory, or capacity.

The 30-student rehearsal is a synthetic capacity prerequisite. It does not
replace the real 5-7 student pilot or the separate-device Setup/LAN preflight.

## Scope Freeze Before Pilot

Keep in v1.0:

- LAN classroom flow and KAI/VPS-ready server mode;
- teacher and student role contracts;
- guided first turn followed by open decisions;
- teacher cockpit, help queue, pause, timer, and turn controls;
- Crisis Cards, causal turn review, results, history, and export;
- Full, Standard, and Lite performance profiles.

Defer until a revision-bound Pilot Gate `PASS` exists:

- new industries beyond the current scenario portfolio;
- player-to-player contracts, alliances, and negotiations;
- complex finance, shares, acquisitions, and permanent MMO progression;
- mobile-first redesign and touch-specific interaction;
- decorative 3D that does not improve a classroom decision.

## Required Verification

npm run check

npm run e2e:classroom
npm run smoke:classroom
npm run rehearsal:classroom
