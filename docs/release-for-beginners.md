# Biz Arena: выпуск и запуск с нулевым опытом работы с серверами

## Самый простой ответ

Для первого занятия домен и отдельный сервер не нужны. Запустите `BizArena Server` на Windows-компьютере преподавателя, подключите его и ученические устройства к одной сети и дайте ученикам QR-код. Игра и все расчёты будут работать на компьютере преподавателя.

Постоянный сервер КАИ нужен позже, когда игра должна открываться по одной стабильной ссылке из разных аудиторий или из дома. Для такого запуска сначала попросите администратора КАИ выделить сервер и поддомен. Покупать личный домен до ответа КАИ не нужно.

## Какой вариант выбрать

| Вариант | Когда использовать | Нужен домен | Нужен интернет | Где работает сервер |
| --- | --- | --- | --- | --- |
| Локальный класс | Первая репетиция, пилот и запасной вариант занятия | Нет | Нет | Windows-компьютер преподавателя |
| Сервер КАИ | Постоянная ссылка и доступ из разных сетей | Желателен поддомен КАИ | Зависит от политики КАИ | Linux-сервер КАИ |
| Обычный VPS | Если КАИ пока не может выделить сервер | Да, для нормального HTTPS-релиза | Да | Арендованный Linux-сервер |

Начните с локального класса. Он проверяет саму игру, действия учеников и преподавателя без риска смешать игровые ошибки с настройкой внешнего сервера.

## Вариант 1 — запустить в локальной сети без домена

### Что понадобится

- Windows-компьютер преподавателя;
- один второй компьютер или телефон для проверки роли ученика;
- общая Wi-Fi или проводная сеть;
- актуальный архив `BizArena-Classroom-<version>.zip` и соответствующий release manifest.

Ученическим устройствам не обязательно устанавливать приложение: они могут открыть ссылку в обычном браузере.

### Первый запуск

1. Распакуйте classroom-архив в отдельную папку.
2. На компьютере преподавателя запустите `BizArena-Server-<version>-Portable-x64.exe`.
3. Если Windows показывает предупреждение для неподписанного приложения, запускайте только файл из проверенного release-архива с совпадающим SHA-256. Не отключайте антивирус или другие средства защиты.
4. Разрешите приложению доступ к частной сети в Windows Firewall. Если системного запроса не было, запустите `tools/Allow-BizArena-Firewall.bat` от имени администратора.
5. На странице преподавателя создайте комнату.
6. Откройте Network Doctor и покажите ученику LAN-ссылку или QR-код.
7. На втором устройстве откройте QR-ссылку в браузере, войдите как ученик и отметьте готовность.
8. Запустите матч, выполните один полный ход, обновите страницу ученика и убедитесь, что он вернулся в ту же компанию.
9. Завершите тестовый матч и проверьте итоговый разбор и экспорт преподавателя.

Адрес ученика выглядит примерно так:

```text
http://192.168.0.10:3000/client
```

Адрес `127.0.0.1` работает только на самом компьютере преподавателя и не подходит ученикам.

Проверить SHA-256 файла в PowerShell можно так:

```powershell
Get-FileHash .\BizArena-Server-<version>-Portable-x64.exe -Algorithm SHA256
```

Полученное значение должно совпадать с `sha256` этого файла в release manifest. Сравнивайте весь хэш целиком, а не только первые или последние символы.

### Если второе устройство не подключается

1. Убедитесь, что оба устройства подключены к одной сети.
2. На ученическом устройстве откройте `http://IP-ПРЕПОДАВАТЕЛЯ:3000/api/health`.
3. Если адрес не открывается, проверьте Windows Firewall и профиль сети: он должен разрешать частную сеть.
4. Если health открывается у преподавателя, но не у ученика, сеть может запрещать связь между клиентами.
5. В этом случае используйте отдельный роутер или точку доступа телефона и повторите проверку.

Не открывайте порт `3000` напрямую в публичный интернет. Локальный режим предназначен для общей доверенной сети класса.

## Вариант 2 — разместить на сервере КАИ

### Что попросить у администратора КАИ

Отправьте администратору следующий список:

- виртуальная машина Ubuntu 22.04 или 24.04;
- Node.js 20 или новее;
- минимум 1–2 vCPU, 2 GB RAM и 10 GB постоянного диска;
- административный доступ по SSH;
- доступ к TCP 80 и 443 из нужной учебной сети;
- поддомен, например `biz-arena.<домен-КАИ>`;
- HTTPS-сертификат;
- разрешённые WebSocket-соединения через nginx;
- постоянное SQLite-хранилище и ежедневное резервное копирование.

Передайте администратору:

- `BizArena-KAI-Server-<version>.zip`;
- `kai-server-release-manifest-<version>.json`;
- эту инструкцию;
- `docs/kai-server-handoff.md` из пакета.

### Нужен ли отдельный домен

Лучший вариант — поддомен существующего домена КАИ. Его создаёт администратор КАИ, поэтому личная покупка обычно не нужна.

Запуск по IP допустим для короткой внутренней проверки. Для постоянной публичной ссылки нужен домен или поддомен и HTTPS: адрес остаётся стабильным, браузер показывает защищённое соединение, а WebSocket работает через тот же защищённый origin.

### Кто за что отвечает

| Вы | Администратор КАИ |
| --- | --- |
| Передаёте проверенный архив и manifest | Устанавливает приложение на Linux-сервер |
| Создаёте первый аккаунт преподавателя | Настраивает DNS, HTTPS, nginx и systemd |
| Проверяете создание комнаты и игровой ход | Закрывает регистрацию после первого аккаунта |
| Проверяете вход ученика, reconnect и экспорт | Настраивает и проверяет backup/restore |
| Проводите пилот с 5–7 учениками | Следит за журналом, диском и доступностью сервера |

Не отправляйте администратору пароли в архиве или GitHub. Первый пароль преподавателя создаётся после установки, а регистрация затем закрывается.

## Когда выпуск можно считать готовым

До передачи преподавателю или КАИ должны быть выполнены все пункты:

- релиз привязан к одному точному Git commit;
- исходное дерево чистое;
- автоматическая release-проверка завершилась без ошибок;
- Server и Client собраны из этого commit;
- packaged Electron smoke завершился успешно;
- SHA-256 каждого файла записан в release manifest;
- отдельное устройство вошло по QR без ручного исправления URL;
- проверены один полный ход, пауза, reconnect, завершение и экспорт;
- для сервера КАИ отдельно проверены HTTPS, WebSocket, перезапуск, SQLite и восстановление из backup.

Локальные автоматические тесты подтверждают код и сборку, но не доказывают политику Wi-Fi аудитории или фактическую настройку сервера КАИ. Эти два пункта проверяются только на реальных устройствах и целевой инфраструктуре.

## Рекомендуемый порядок

1. Собрать чистый релиз-кандидат.
2. Запустить Server на компьютере преподавателя.
3. Подключить одно отдельное ученическое устройство.
4. Провести короткую репетицию с 5–7 участниками.
5. Передать тот же неизменённый KAI-пакет администратору.
6. Повторить двухустройственную проверку уже по адресу КАИ.
7. Только после этого проводить полноценное занятие.
