# Biz Arena v0.1 — stabilization phase 2

Вторая фаза после Milestone 11 продолжает стабилизацию, но уже смещает фокус с ручного bug bash на hardening, интеграционные проверки и regression coverage.

## Цель фазы

- перевести критичные сценарии из ручного smoke в повторяемые интеграционные проверки;
- закрыть самые уязвимые места между room lifecycle, game loop и Intel/queue UX;
- подготовить backlog для более глубокого persistence/runtime hardening;
- уменьшить риск регрессий перед следующим milestone.

## Scope

### 1. Integration smoke coverage

Автоматизировать базовые happy-path сценарии:

1. lobby → join → ready → start-game;
2. базовый игровой цикл с бизнес-действием и хотя бы одним тиком;
3. Intel flow: получение CEO brief, обновление focus-plan, refresh pivot preview и execution queue;
4. results flow после завершения сезона.

### 2. Regression packs

Отдельно собрать регрессионные наборы для:

- contracts;
- research;
- season goal progress;
- save / load snapshot flow;
- execution queue и actionable Intel;
- operating plans и их влияние на матч до и после тика.

### 3. Server-level hardening checks

Добавить интеграционные сценарии поверх реального room state, а не только моков:

- несколько действий подряд от одного игрока;
- хостовые действия и переходы статусов комнаты;
- корректность player-scoped state после изменений;
- восстановление состояния после load/save;
- отсутствие критичных сбоев при пограничных условиях сезона.

### 4. Runtime backlog preparation

В конце фазы собрать отдельно приоритизированный backlog на следующую стадию:

- persistence hardening;
- recovery / error handling;
- LAN-runtime polish;
- reconnect / refresh устойчивость;
- data validation и schema versioning.

## Smoke matrix

#### Smoke A — room lifecycle

- host создаёт комнату;
- второй игрок входит;
- оба игрока готовы;
- матч стартует и переходит в running;
- host умеет pause / resume без разрушения state.

#### Smoke B — core tick

- игрок делает одно бизнес-действие;
- проходит тик;
- деньги, склад, last action и last tick breakdown меняются ожидаемо.

#### Smoke C — strategic layer

- Intel summary присутствует;
- focus-plan меняется и отражается в state;
- pivot preview обновляется;
- execution queue перестраивается после действия;
- actionable queue step выполняется без server-side ошибки.

#### Smoke D — persistence

- хост сохраняет комнату;
- матч уходит в другое состояние;
- save загружается;
- ключевые поля room/player/account корректно возвращаются.

## Артефакты фазы

К концу фазы должны быть готовы:

- integration smoke suite;
- regression checklist по уязвимым системам;
- список известных runtime/persistence рисков;
- решение, что идёт в следующую фазу hardening, а что остаётся в backlog.

## Definition of done

Фаза считается завершённой, когда:

- ключевые пользовательские сценарии проходят не только вручную, но и через повторяемые integration smoke checks;
- регрессии по Intel, queue, contracts, research и save/load закрыты минимальным автоматическим покрытием;
- room lifecycle стабилен на happy path;
- следующий backlog hardening разбит по приоритетам и подтверждён фактами из smoke/regression результатов.

## Out of scope

Фаза 2 не включает:

- полное переписывание storage;
- переход на новую БД;
- полноценный production-grade deploy pipeline;
- новый gameplay milestone;
- глубокую переработку UI-дизайна.

Это остаётся на следующих стадиях hardening; ближайшая из них описана в `docs/v0.1-stabilization-phase-3.md`.
