# Biz Arena v0.9: Pilot Readiness

Дата старта: 2026-06-29

## Цель

Подготовить Biz Arena к первому реальному занятию в КАИ. В этом цикле новые экономические механики не добавляются. Приоритет: преподаватель управляет классом без поиска нужной кнопки, ученик проходит первый ход без устной навигации по интерфейсу, а сбой подключения не ломает занятие.

## Критерии пилота

### До занятия

- преподаватель запускает Server или открывает KAI URL и видит health/storage status;
- комната создается не более чем за 2 минуты;
- ссылка, QR и код комнаты находятся в одном блоке;
- до старта видно, кто вошел, кто готов и кого еще ждут;
- в лобби есть ровно одно основное действие для каждой роли.

### Старт класса

- ученик входит по ссылке или коду не более чем за 60 секунд;
- ученик видит себя, преподавателя, состав класса и параметры занятия;
- одна кнопка подтверждает участие;
- преподаватель запускает матч одной кнопкой только после readiness gate;
- после старта обе роли автоматически получают понятный следующий экран.

### Первый ход

- маршрут ученика: Купить -> Нанять -> Собрать -> Продать -> Завершить ход;
- на экране одновременно выделено одно основное следующее действие;
- ошибка объясняет причину и способ исправления рядом с действием;
- преподаватель видит команды без покупки, работников, сборки и заявки;
- застрявшая команда находится в cockpit не более чем за 15 секунд.

### Сбой и восстановление

- обновление страницы восстанавливает комнату и роль по session token;
- повторный вход с тем же именем не создает дубликат команды;
- отключение WebSocket не ломает HTTP polling fallback;
- после перезапуска KAI/VPS сервера SQLite восстанавливает аккаунт и комнату;
- преподавателю доступны health, журналы, backup и restore.

### Завершение

- преподаватель может поставить паузу, продолжить, перейти к следующему ходу и завершить матч;
- ученику показывается персональный разбор результата;
- преподавателю показываются общие ошибки класса и вопросы для обсуждения;
- результаты можно экспортировать для отчета по занятию.

## Product Scope

### Оставить на основном пути

- Local Classroom и KAI/VPS Classroom;
- teacher accounts и guest students;
- teacher lobby command center и in-game teacher cockpit;
- student lobby и guided first turn;
- Crisis Cards;
- Network Doctor для локального fallback;
- SQLite, WebSocket invalidation и polling fallback;
- class/player debrief.

### Свернуть во вторичный уровень

- save/load/reset и добавление ботов;
- глубокую аналитику и experiment runner;
- расширенные настройки скорости;
- подробные таблицы и технические данные сервера.

Эти функции остаются доступными, но не конкурируют с основным действием текущего этапа занятия.

### Не возвращать

- Cloudflare quick tunnel;
- P2P/WebRTC;
- Oracle-only инструкции;
- несколько одинаковых CTA на одном экране;
- старые release-файлы и инструкции с прежними версиями.

## Первый результат

29 июня устранено дублирование lobby UX:

- teacher lobby содержит один `start-game` CTA;
- student lobby содержит одну кнопку готовности;
- общая classroom hero не рендерится поверх ролевого lobby UX;
- вторичные host-команды отделены от запуска матча;
- browser E2E проверяет эти инварианты без screenshot-тестов.

## Реализованный pilot pass

29 июня выполнены основные UX и reliability-критерии:

- teacher cockpit содержит одну панель управления и один блок текущих задач;
- первый ход ученика содержит один основной CTA вместо двух адаптивных копий;
- refresh/reconnect сохраняет student session, lite mode и текущее следующее действие;
- teacher lobby показывает preflight `5/5` и требует хотя бы одного ученика до старта;
- итоговый экран уже содержит личный и классовый debrief, вопросы для обсуждения и JSON-экспорт;
- rehearsal на 30 учеников и 30 WebSocket-соединений прошел без ошибок;
- при rehearsal получены `state p95 = 32 ms`, `action p95 = 27 ms` при лимитах 750/1000 ms.
