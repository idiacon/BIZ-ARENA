# Biz Arena v0.1 — stabilization phase 3

Третья фаза после Milestone 11 завершает базовый цикл hardening и переключает основное внимание на persistence, recovery и устойчивость runtime-сценариев в LAN-хостинге.

## Цель фазы

- снизить риск потери или порчи состояния комнаты и аккаунтов;
- сделать save/load и восстановление более безопасными;
- подготовить storage-слой к дальнейшим изменениям формата данных;
- укрепить host/runtime-поток перед следующим продуктовым этапом.

## Scope

### 1. Persistence safety

Добавить и проверить:

- atomic write для JSON storage;
- backup / fallback snapshot strategy;
- корректное поведение при прерывании записи;
- защиту от частично повреждённого состояния данных.

### 2. Schema / validation layer

Подготовить слой совместимости:

- `schemaVersion` для storage и snapshot payloads;
- минимальную валидацию room / player / account shape;
- fallback на безопасные значения при чтении старых или неполных данных;
- правила для будущих миграций.

### 3. Save / load recovery flow

Проверить и укрепить:

- загрузку сохранения после изменений room state;
- поведение при несовместимом snapshot;
- сообщения об ошибках для хоста;
- откат на последнее валидное состояние при неуспешной загрузке.

### 4. Runtime resilience

Сфокусироваться на LAN/runtime-устойчивости:

- refresh страницы во время матча;
- повторный вход игрока в существующую комнату;
- обработка временно недоступного server response;
- предсказуемый feedback после host-side ошибок;
- сохранение понятного состояния UI при transient failures.

## Smoke matrix

#### Smoke A — storage write

- игра создаёт/обновляет JSON storage;
- данные сохраняются без разрушения структуры;
- повторное чтение возвращает валидный state.

#### Smoke B — snapshot recovery

- host делает save;
- room заметно меняет состояние;
- load восстанавливает snapshot;
- при ошибке load показывается понятный feedback и room не остаётся в полусломанном состоянии.

#### Smoke C — invalid data handling

- система сталкивается с неполным или устаревшим state;
- unsafe payload не приводит к silent crash;
- используются fallback/default значения или возвращается контролируемая ошибка.

#### Smoke D — runtime resilience

- игрок обновляет страницу во время сессии;
- host продолжает матч;
- клиент снова получает player-scoped state;
- UI возвращается в понятное состояние без полного развала flow.

## Артефакты фазы

К концу фазы должны быть готовы:

- storage hardening checklist;
- список validation / migration правил;
- recovery сценарии для save/load;
- backlog оставшихся runtime/LAN проблем;
- решение, какой следующий продуктовый этап открывать после стабилизации v0.1.

## Definition of done

Фаза считается завершённой, когда:

- JSON storage переживает обычные save/update сценарии без порчи данных;
- save/load не оставляет room в промежуточном неконсистентном состоянии;
- невалидные или устаревшие данные обрабатываются контролируемо;
- основные LAN/runtime ошибки не превращают UI в тупиковое состояние;
- можно зафиксировать, что v0.1 прошёл базовый stabilization + hardening цикл.

## Out of scope

Фаза 3 не включает:

- переход на полноценную внешнюю БД;
- production auth / multi-tenant backend;
- полный online-service rollout;
- новую крупную экономическую механику;
- редизайн клиентского интерфейса.

После этой фазы начинается финальная release-readiness стадия, описанная в `docs/v0.1-stabilization-phase-4.md`.
