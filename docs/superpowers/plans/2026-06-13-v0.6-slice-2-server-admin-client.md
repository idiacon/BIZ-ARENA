# v0.6 Slice 2 Server/Admin/Client Split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `/server` and `BizArena Server.exe` feel like a teacher/admin cockpit, while `/client` and `BizArena Client.exe` stay focused on student entry and gameplay. Preserve all v0.5 Local Classroom and Cloud Classroom APIs.

**Architecture:** Keep one Node app and one static browser shell for this slice. Do not introduce React/Next or a new build step. Split behavior through clearer view-mode gates, render helpers and contract tests before moving files.

**Tech Stack:** Node.js, Electron 30, vanilla JS, CSS, built-in `node:test`, existing smoke scripts.

---

## Scope

In scope:

- harden route/mode contracts for `/server`, `/client`, desktop server mode and desktop client mode;
- make server mode prioritize teacher cockpit, class readiness and classroom control;
- make client mode prioritize room entry, ready state and guided first turn;
- keep player actions and teacher/admin actions visibly separate in code and tests;
- add regression tests before UI edits.

Out of scope for this slice:

- SQLite adapter;
- full Thin Client v2 read model rewrite;
- new cloud hosting provider work;
- new simulation/economy mechanics;
- large CSS redesign.

## Tasks

- [ ] Add contract tests for route/mode separation.
  - File: `test/stabilization.test.js`.
  - Assert `public/index.html` still has distinct server/admin and student/client shells.
  - Assert `public/app.js` contains explicit server-mode and client-mode gates for major render paths.
  - Assert student mode does not call `/api/server/action` or `/api/teacher/action` from student-only controls.
  - Keep these as source contract tests until browser automation is available.

- [ ] Add API boundary tests for teacher/admin actions.
  - File: `test/server-refactor.test.js`.
  - Verify `/api/server/action` remains localhost-only for Local Classroom.
  - Verify `/api/teacher/action` requires teacher session and room ownership in Cloud Classroom.
  - Verify `/api/action` continues to resolve player identity from `sessionToken`, not claimed `playerId`.

- [ ] Refactor `public/app.js` mode helpers without behavior change.
  - Add small helpers such as `isServerMode()`, `isClientMode()`, `isTeacherView()` only if they reduce duplicated checks.
  - Keep existing global state shape.
  - Do not move to modules in this slice unless the tests prove a very small extraction is safe.

- [ ] Make `/server` first screen a teacher cockpit.
  - Preserve Network Doctor and QR for Local Classroom.
  - Put room code, student link, QR, health and class readiness above gameplay-heavy panels.
  - Keep controls: pause, resume, next turn, finish.
  - Add "what to do now" copy as compact operational status, not a marketing description.

- [ ] Make `/client` first screen student-only.
  - Show one primary flow: join room, enter name/company, mark ready.
  - Keep lite mode visible and persistent.
  - Hide teacher/admin vocabulary from client mode unless the student is already inside a match and the shared game tab requires neutral labels.

- [ ] Add stuck-team signals to teacher cockpit.
  - Reuse existing teacher overview/readiness data first.
  - Show connected, ready, no purchase, no workers, no assembly, no sale and bankruptcy risk.
  - Do not create new game mechanics; this is a read-model/UI pass.

- [ ] Update smoke scripts for the split.
  - File: `scripts/smoke-classroom-lan.js`.
  - File: `scripts/smoke-cloud-classroom.js`.
  - Add assertions that `/server` exposes teacher cockpit markers and `/client` exposes student entry markers.
  - Keep smoke scripts deterministic and headless.

- [ ] Verify.

  - Run `npm test`.

  - Run `npm run smoke:cloud`.
  - If Electron tooling is available, run packaged or desktop mode smoke for server/client routing.
