# BIZ-ARENA — Studio Art Direction v3

Дата: 2026-08-29.

## Главная идея

**Operational Classroom Studio** — учебная бизнес-симуляция должна ощущаться как настоящий операционный продукт, но оставаться понятной в классе с первого взгляда.

Главная коммуникационная задача: в каждый момент пользователь без чтения инструкции понимает свою роль, текущее состояние и следующее действие.

## Визуальная территория

- индустриальный тёмно-синий canvas вместо безликого игрового фона;
- холодный фиолетово-синий бренд BIZ-ARENA как цвет основного действия;
- cyan для живого состояния, сети и преподавательского контроля;
- amber только для внимания, риска и итоговых акцентов;
- restrained depth: уровни поверхности и свет вместо рамки вокруг каждого элемента;
- IBM Plex Sans / Condensed для интерфейса и Fira Code только для кодов, времени и чисел;
- никакого внешнего font CDN: класс и Electron/LAN-сценарии должны работать офлайн.

## Ролевые композиции

### Server/Admin

Главный фокус — запуск занятия. До создания комнаты интерфейс показывает только создание игры и выход. После создания — здоровье сервера, вход учеников и lifecycle матча.

### Teacher

Главный фокус — состояние класса и следующее педагогическое вмешательство. Cockpit строится из трёх зон: состояние класса, рабочий dashboard, lifecycle/actions. Cyan обозначает контроль и live-состояние, но не конкурирует с основным CTA.

### Student

Главный фокус — одна кнопка следующего шага. Маршрут `Купить → Нанять → Собрать → Продать → Завершить ход` остаётся видимым, а поддерживающие метрики становятся тише. Teacher/admin controls отсутствуют, а не просто скрыты данными.

### Results

Главный фокус — объяснимый итог: место, изменение бизнеса и причина результата. Amber используется как наградной/итоговый акцент, а не как постоянный декоративный цвет.

## Композиционные правила

1. На экране ровно один доминирующий action.
2. Статус и данные поддерживают решение, но не выглядят как одинаковые CTA.
3. Вложенные карточки используют не больше двух уровней сильной поверхности.
4. На desktop рабочая ширина до 1600 px; на tablet teacher cockpit становится одноколонным.
5. На mobile navigation и HUD занимают минимум высоты, после них сразу идёт основная работа роли.
6. Иконки берутся из существующего SVG sprite; emoji не используются как интерфейсные пиктограммы.

## Accessibility и motion

- body text поддерживает контраст не ниже 4.5:1;
- keyboard focus всегда видим и не зависит только от цвета;
- интерактивная цель не меньше 42 px, primary mobile action — не меньше 48 px;
- `prefers-reduced-motion` отключает декоративные переходы, пульсации и смещения;
- Lite Mode остаётся самостоятельной производительной веткой без теней и фильтров;
- экраны проверяются на 375, 768, 1024 и 1440 px без горизонтального переполнения.

## Anti-slop veto

- запрещены purple-to-pink gradients на всех ключевых кнопках;
- запрещены случайные декоративные glow, glass и масштабирование карточек;
- запрещены одинаково сильные рамки вокруг каждой строки;
- запрещены вторичные действия, визуально равные primary action;
- запрещено смешивать Server/Admin, Teacher и Student surfaces ради симметрии макета.
